# A7C II FL23 Linux

持续适配 [QAQLeonard/a7c2-fl23-research](https://github.com/QAQLeonard/a7c2-fl23-research) 的 Linux 一键交互脚本。运行 `sh a7c2-linux.sh`，自动准备固定版本的上游和本目录 Python venv，然后按菜单编号使用。

脚本负责依赖准备、命令行交互与 Linux USB 通信适配；相机读写、外观和声音转换、备份及恢复事务由上游实现。可执行入口只有一个 `a7c2-linux.sh`，无需手动创建 Python 文件或启动图形界面。

**当前支持 Sony A7C II（ILCE-7CM2），固件 2.01。2026-10-27，Mulei Zhang 已在 Fedora Linux 44 Workstation、x86_64 的本机上完成初版（`606968c`）开放功能的实机测试，确认正常。** 此后新增的竖屏开启／关闭和含竖屏的组合安装已接入，尚待本脚本实机验证，不沿用初版的实测结论。

## 快速开始

把脚本放在有写入权限的目录，以普通用户运行：

```sh
sh a7c2-linux.sh
```

首次启动会下载固定提交的上游源码，在脚本所在目录的 `a7c2-linux-data/.venv` 中创建 Python 环境并安装依赖。后续启动复用缓存，检查上游来源、提交和工作树是否与预期一致。首次准备需要网络。

将相机设为海量存储模式，仅连接一台 A7C II，在菜单输入 `1` 检查连接。确认操作时输入 `1`；输入 `0` 或直接回车取消。文件路径、槽位和音频裁剪时间等参数按提示填写。

写入前会显示操作摘要，并要求确认机型、固件、电量至少 50% 和稳定供电。恢复 ST 或原厂功能可能覆盖自订配方；请先保留重要数据与备份。若上游提示断电重启，按提示操作，再选择 `15` 继续／核对。

## 环境要求

| 依赖 | 用途 |
| --- | --- |
| Bash、Git、jq | 脚本、固定版本下载、JSON 参数与状态读取 |
| Python **3.11**，含 venv | 需能运行 `python3.11`；脚本自动创建目录内 venv，不向全局 Python 安装依赖 |
| flock（通常在 util-linux 中） | 防止多个实例同时运行 |
| GNU coreutils、awk、sed | 路径、文件与日志处理，主要 Linux 发行版通常已提供 |
| udisksctl（通常在 udisks2 中） | 相机分区被挂载时自动卸载 |
| systemd-inhibit（可选） | 相机操作期间阻止休眠，存在时自动使用 |

上游所需的 Python 包、libusb 包和 Zig 工具链由脚本在本目录 venv 中安装，跳过图形界面依赖 PySide6。脚本不会安装系统软件包、执行 sudo 或修改系统 USB 规则。

适配目标包括 Debian/Ubuntu、Fedora/RHEL、Arch 和 openSUSE。**已实测的是上述 Fedora 44 x86_64 环境**；其他发行版、CPU 架构、Python 3.11 的安装方式和依赖包可用性仍需验证，不能把适配目标视为已测试矩阵。

### USB 权限

首次使用可查看管理员准备说明：

```sh
sh a7c2-linux.sh usb-help
```

相机的普通身份 `054c:0e8a` 和服务身份 `054c:0336` 都需要当前用户具备访问权限。脚本会展示 udev 配置示例，由管理员按需执行；SSH／无桌面会话需要相应的用户组权限配置。

普通身份应先由 `usb-storage` 完成初始化，不要设置忽略相机的 usb-storage quirks。脚本会检查身份和权限、卸载相机分区并复查挂载状态，再调用上游 libusb 的驱动解绑方法。遇到权限、驱动或占用问题时会停止并提示原因。

## 菜单功能

| 编号 | 功能 |
| --- | --- |
| 1 / 2 | 检查连接／USB 稳定性，只读；稳定性检查至少两分钟 |
| 3 | 选择并组合安装 FL2/FL3、原生快门声、竖屏显示、自定义 A7Look |
| 4 / 5 | 启用／移除 FL2、FL3 菜单入口 |
| 6 / 7 | 导入 A7Look 到自订 1–6／将选定槽位恢复为 ST |
| 8 | 离线转换 DCP、CUBE 为 A7Look；CUBE 必须为 Sony ST/sRGB，不能直接使用 Log LUT |
| 9 / 10 / 11 | 开启原生快门声／关闭声音／恢复原厂音效 |
| 12 / 13 | 离线转换音频或视频中的声音／安装已转换的自定义快门声 |
| 14 | 恢复本项目涉及的原厂功能，自订 1–6 全部设为 ST |
| 15 | 继续上次操作／重启后核对，依据上游保存的事务状态处理 |
| 16 / 17 / 18 | 查看记录与导出诊断／USB 权限说明／使用历史备份回退 |
| 19 / 20 | 开启竖屏显示与 Fn／子菜单显示修正／关闭竖屏并撤销显示修正 |
| 0 | 退出 |

声音转换需填写起点秒数和长度（0.01–2 秒），然后通过 `13` 安装。导入外观使用自己的 A7Look 文件；上游另行发布的预设外观包不随本仓库提供。

### 竖屏显示

竖握相机时让拍摄信息、图标和布局转向，整个 MENU 不旋转。菜单 `19` 保存开启开关并应用上游 Fn／子菜单显示修正；`20` 先关闭竖屏，再撤销相关显示修正。菜单 `3` 也可以勾选竖屏，或只选择竖屏安装。

按提示完整断电重开后，检查横握、左右竖握时的 Fn 网格、创意外观选择页、参数调整页，以及拍摄和回放，再选 `15` 继续／核对。独立竖屏任务会重新调用同一上游入口，读取当前状态并创建新的检查／操作记录；内容已符合目标时，上游返回 `LOADED`，不重复写入。失败后保留原记录，也通过 `15` 明确确认后续接，不自动重放旧写入请求。续接仍按可能写入的操作确认。

固定上游已提供竖屏实现，但其文档仍标注菜单线框重写中、待实机验收。已知显示问题包括创意外观页外框偏粗、橙色刻度指针朝向尚未修正。本脚本新增竖屏功能尚待实机验证，执行前会单独提示。

## 命令行入口

| 命令 | 行为 |
| --- | --- |
| `sh a7c2-linux.sh` | 准备环境并进入交互菜单，需要终端 |
| `sh a7c2-linux.sh setup` | 下载固定上游、准备 venv 与依赖，不访问相机 |
| `sh a7c2-linux.sh doctor` | 准备环境并输出依赖诊断，不访问相机 |
| `sh a7c2-linux.sh status` | 显示当前相机任务保存的状态，不发起相机操作 |
| `sh a7c2-linux.sh continue` | 交互续接或核对当前任务，可能访问／写入相机 |
| `sh a7c2-linux.sh usb-help` | 显示 USB 权限与管理员配置说明 |
| `sh a7c2-linux.sh test` | 运行脚本自检和选定的上游离线测试，不访问相机 |
| `sh a7c2-linux.sh help` | 显示内置帮助 |

除 `help`、`usb-help` 外，这些公开入口都会先准备并检查环境。`test` 会在目录内 venv 安装测试依赖；它运行的是精简自检，不等同于下述完整上游测试。

## 数据、日志与恢复

下载的源码、venv、缓存、任务、备份和日志均保存在脚本旁的 `a7c2-linux-data/`。该目录会生成忽略规则，运行数据不进入 Git 提交。

任务日志路径会在操作时显示，也可用菜单 `16` 查看记录、导出诊断。诊断可能含本机路径，分享前请检查内容。失败时保留原记录，通过 `15` 或 `continue` 按上游事务状态继续；脚本不会自动重试写入。

更新、移动目录或清理磁盘前请保留完整运行数据。不要删除备份、任务或 `state/current` 来绕过未完成状态，也不要在任务未完成时更换适配版本。

## 持续适配与版本更新

本项目持续跟进上游，**每次适配锁定一个完整 Git 提交**，不会在启动时自动追踪上游 main 或 latest。

| 记录日期 | 固定上游提交 | 验证状态 |
| --- | --- | --- |
| 2026-10-27 | [`ef7db116e13e37be91e9af20360dc9bba8d64a9b`](https://github.com/QAQLeonard/a7c2-fl23-research/commit/ef7db116e13e37be91e9af20360dc9bba8d64a9b) | 初版 `606968c` 的开放功能已在 Fedora 44 x86_64 + A7C II 2.01 实测；随后新增竖屏接入，待实机验证 |

维护新适配版本时：

1. 选择上游提交，核对接口、依赖、机型／固件要求和事务格式变化。
2. 调整脚本的 Linux 适配与调用，更新 `COMMIT`，继续复用上游读写和状态处理。
3. 运行脚本自检、USB 模拟、离线转换与相关上游测试；记录失败和跳过原因。
4. 记录该版本的实机测试环境与功能范围，再更新本表并提交。未实测的新版本明确标注为未实测，不继承旧版验证结论。

使用者更新本仓库或替换脚本后，运行 `sh a7c2-linux.sh setup`。新固定提交会下载到新的 `upstream-<提交号>` 目录；依赖清单改变时重新安装到同一个目录内 venv。旧源码和运行数据不会自动删除。源码来源、提交或内容被改动时，脚本会停止，避免覆盖缓存或混用版本。

自动化结果与实机报告共同说明当前验证进度；尚未完成多发行版、多架构以及无缓存首次安装的测试矩阵。
